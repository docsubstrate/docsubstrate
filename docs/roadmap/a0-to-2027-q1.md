# A0 roadmap through 2027 Q1

Status: capacity-constrained planning draft for one maintainer working with LLM
assistance. Dates express order and review windows, not promises.

## Operating constraints

- Keep one architecture/profile milestone and one bounded proving milestone in
  flight at most.
- A model may help map vocabularies, generate fixtures, and find
  counterexamples. Acceptance remains deterministic and test-backed.
- Domain pressure may produce a vocabulary, profile, or adapter. It does not
  modify the generic core unless the existing owners fail a cross-domain test.
- Every demonstration must run after its source application and the
  `docsubstrate` Python package are removed from the reader process.

## Per-milestone release gate

Each milestone closes only when all of the following are true:

1. the exact profile/vocabulary version and test fixture are recorded;
2. positive and negative cases pass in an isolated environment;
3. the independent reader requires no source-system vocabulary unless the
   profile explicitly declares it;
4. no production, customer, credential, private-key, or restricted evidence is
   present in files or reachable Git history;
5. any discovered generic gap is written as a falsifiable proposal and reviewed
   separately from the proving implementation; and
6. the public limitations say what remains unproven.

## Explicitly deferred

- a universal commerce, clinical, authority, or workflow ontology;
- a proprietary cryptographic format;
- real patient or customer data in public fixtures;
- claims that the first Odoo engine fully replaces every report path;
- stable public wire/API guarantees before the profiles survive the two proving
  grounds above.
